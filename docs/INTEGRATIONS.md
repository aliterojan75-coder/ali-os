# اتصال‌ها (Integrations) — §3، §20

Ali OS اطلاعات دسترسی سرویس‌های بیرونی را **از داخل خود اپلیکیشن** می‌گیرد:
داشبورد (Mini App) → تب **🔌 اتصال‌ها**. نیازی به دست‌زدن به کد یا فایل env نیست.

## راه‌اندازی اولیه (یک‌بار)

اپلیکیشن بدون کلید رمزنگاری، هیچ اطلاعات محرمانه‌ای را ذخیره نمی‌کند:

```bash
python -m app.tools.gen_key
# ENCRYPTION_KEY=... را در متغیرهای محیطی سرور بگذار
```

اگر این کلید نباشد، تب اتصال‌ها یک هشدار قرمز نشان می‌دهد و ذخیره را رد می‌کند —
این عمدی است تا رمزها ناخواسته بدون رمزنگاری در دیتابیس ننشینند.

> ⚠️ عوض‌کردن کلید = غیرقابل‌خواندن‌شدن اتصال‌های قبلی (باید دوباره وارد شوند).

## سرویس‌های موجود

| سرویس | فاز | چه چیزی لازم دارد |
|-------|-----|-------------------|
| 🌐 WordPress / WooCommerce | ۲ | آدرس سایت + نام کاربری + **Application Password** |
| 📣 کانال تلگرام | ۲ | شناسه کانال (بات باید ادمین باشد) |
| ✉️ ایمیل (SMTP) | ۲ | هاست، پورت، کاربر، رمز |
| 🔍 Google Search Console | ۳ | Property + OAuth (Client ID/Secret/Refresh Token) |
| 📈 Google Analytics GA4 | ۳ | Property ID + همان OAuth |
| 💸 Google Ads | ۴ | 🔒 نیازمند Developer Token (تأیید گوگل) |
| 📍 Google Business Profile | ۴ | 🔒 نیازمند فرم درخواست API |
| 📸 Instagram | ۴ | 🔒 نیازمند Business Account + اپ تأییدشده‌ی Meta |

سرویس‌های 🔒 در UI دیده می‌شوند اما فرمشان غیرفعال است و دلیل مسدودبودن را
توضیح می‌دهند — تا معلوم باشد محدودیت سیاستی است، نه فراموشی.

## WordPress — چرا Application Password؟

رمز اصلی حساب هرگز لازم نیست. در پیشخوان: **کاربران → پروفایل → Application
Passwords** یک رمز اختصاصی برای «Ali OS» بساز. هر زمان بخواهی از همان‌جا لغو
می‌شود، بدون عوض‌کردن رمز اصلی.

بعد از ذخیره، Ali OS بلافاصله اتصال را **تست می‌کند** و می‌گوید:
- کاربر با چه نقشی وصل شده،
- آیا WooCommerce فعال است،
- و اگر نقش کاربر اجازه‌ی انتشار ندارد، هشدار می‌دهد.

## امنیت

- مقادیر محرمانه با **Fernet** (AES-128-CBC + HMAC) رمز می‌شوند و بعد ذخیره.
- فیلدهای غیرمحرمانه (مثل آدرس سایت) جدا در `public_json` می‌مانند تا قابل نمایش باشند.
- API هرگز مقدار کامل یک Secret را برنمی‌گرداند — فقط نسخه‌ی ماسک‌شده (`••••1234`).
- هنگام ویرایش، خالی‌گذاشتن فیلد رمز یعنی «همان قبلی بماند».
- کلید فقط از env خوانده می‌شود؛ نه در کد است، نه در گیت.

## استفاده از داخل کد

```python
from app.integrations import store

creds = store.credentials("wordpress", project_id)   # رمزگشایی‌شده
site   = creds["site_url"]
```

## افزودن یک سرویس جدید

فقط یک ورودی به `app/integrations/catalog.py` اضافه کن — فرم UI خودکار ساخته می‌شود:

```python
Service(
    slug="my_service", name="سرویس من", icon="🔧",
    category="ابزار", phase=3, summary="…",
    fields=[
        Field("api_key", "API Key", "password", secret=True,
              help="از پنل سرویس بگیر"),
    ],
)
```

برای تست اتصال، یک تابع در `app/integrations/testers.py` بنویس و در `TESTERS` ثبت کن.

## WordPress Agent

اکشن‌های زیر ثبت شده‌اند و همگی از دروازه‌ی تأیید رد می‌شوند
(جزئیات در [`APPROVALS.md`](APPROVALS.md)):

| اکشن | ریسک |
|------|------|
| `wordpress.create_draft` | 🟡 یک تأیید |
| `wordpress.update_post` | 🟡 یک تأیید |
| `wordpress.publish` | 🔴 دو تأیید |
| `wordpress.delete_post` | 🔴 دو تأیید (به زباله‌دان، نه حذف دائم) |

خواندن نیازی به تأیید ندارد: `list_posts()`، `list_categories()` و
`content_index()` (همان بررسی ضد-Cannibalization که قوانین گیاهکده می‌خواهد).
